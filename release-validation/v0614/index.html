Verdict

Section titled “Verdict”

✅ Ship. The published artifact deploys in all six shipped configurations, including the new TenantIsolationMode=Strict configuration, whose isolation harness passed 23 of 23 checks. Both template transforms deploy and process a real document. The upgrade from 0.6.13 completed without a version effect on extracted values, and the 342-run release A/B shows 0 regressions and 0 improvements, with recall and cell accuracy identical on both sides over the same 23,370 compared cells. All four security gates pass. The two RBAC counts that moved are exactly the four tenant-administration operations this release adds.

All 8 tiers have a result. Tiers A–E, G and H and F1 are recorded here. Tier F’s guidance refresh (F2–F4) is reported in the sibling benchmark pull request, #1823. Six of its thirty lanes were killed by a host restart on 2026-11-07 and re-run in full, with the fifteen lanes that had not started, from 2026-11-09 (see Tier F).

The finding that matters most for a customer is in the upgrade path, and it is environmental in trigger but not in effect. The first update-stack attempt failed because the container-image build in the multi-document-discovery nested stack did not finish within its custom resource’s time budget. The rollback then failed on the same resource, leaving the stack in UPDATE_ROLLBACK_FAILED until continue-update-rollback was run by hand. The second attempt, with CodeBuild dispatching normally, completed in 25 m 41 s. A customer whose CodeBuild builds queue during an upgrade would reach the same state. Finding 1, filed as #1824.

This release closes all five product defects the v0.6.13 record filed. Per-section Re-extract no longer rewrites every section’s class (#1672). It ran correctly in the browser review. The SDK’s minimal configuration now validates (#1673), and the SDK integration suite passes 13 of 13 where it failed 1 of 13 at v0.6.13. The packet-window (#1676), blank-page (#1677) and confidence-step memory (#1678) fixes are measured by the benchmark refresh. This record files two Test Studio defects: one introduced in this release (Finding 2, #1816), and one whose first appearance was not checked against v0.6.13 (Finding 3, #1817).

Tier D — template transforms, and the limits of a commercial-region run

Section titled “Tier D — template transforms, and the limits of a commercial-region run”

Both transforms deployed and processed samples/lending_package.pdf end to end. The document was classified Payslip with 17 of 22 fields populated; v0.6.13 populated 18. One run per transform per release cannot separate a version effect from run-to-run variation on this document, which Finding 4 measures directly across seven runs and attributes to variation.

  • --headless: the transform removed 99 of 356 resources (UI, Cognito and CloudFront), removed the six policy statements that referenced them, and disabled the Knowledge Base.
  • --govcloud: the transform removed the AWS::Lambda::Url resource and the LWA chat-stream function (#677), collapsed 21 CloudFront-hosting conditions to the API Gateway branch, and forced WebUIHosting=APIGateway. ⚠️ The --govcloud result is a commercial-partition result. It proves the CloudFront-free, API-Gateway-hosted template deploys and processes documents. It proves nothing about partition ARNs, GovCloud model availability or the BDA project rejection (#676/#677 were invisible to a commercial run). The Knowledge Base was disabled in the --govcloud run, which is the runner’s default.

Findings, most important first

Section titled “Findings, most important first”

1. An upgrade whose container build does not finish in time fails, and so does its rollback (product robustness, environment-triggered)

Section titled “1. An upgrade whose container build does not finish in time fails, and so does its rollback (product robustness, environment-triggered)”

Tier E’s first update-stack started at 23:08 UTC. The DockerBuildRun custom resource in the multi-document-discovery nested stack failed twice with Build … did not complete within the Lambda budget. Its counterpart in the unified pattern stack was cancelled, then failed during rollback with build did not complete - status: [STOPPED]. The parent reached UPDATE_ROLLBACK_FAILED at 23:42 UTC. continue-update-rollback at 00:35 UTC returned it to UPDATE_ROLLBACK_COMPLETE at 00:49 UTC, and the second attempt completed normally. The hosting-private stack-test, created at the same time, failed on the same resource and reached ROLLBACK_FAILED.

The trigger was environmental: the builds those resources start did not complete in time, during a window in which the run’s notes record CodeBuild builds in the account as not dispatching. The logs here do not establish why, or whether the queueing was account-wide. Once builds were dispatching again, both stacks deployed. The effect on a customer is not environmental: an upgrade during a CodeBuild slowdown does not simply fail and roll back. It leaves the stack needing a manual continue-update-rollback. The repository’s test-upgrade skill gives that command for a rollback deadlock, but no customer-facing page described this case at this release. Filed as #1824 and fixed in #1825, which also adds the recovery to Troubleshooting. The evidence is two occurrences in this pass, both on DockerBuildRun (tier E’s first attempt and the hosting-private stack-test’s first attempt), and the cause of the stall is not established.

2. Test Studio’s Re-extract offer after a class change is lost on reload, and a second change names the wrong class (product defect, this release)

Section titled “2. Test Studio’s Re-extract offer after a class change is lost on reload, and a second change names the wrong class (product defect, this release)”

Tier G, flow 6.2. After a section’s class is changed with Edit Page Grouping, the editor offers per-section Re-extract with the note “These fields were extracted as class”. That offer is held only in React state (reclassified in test-set-editor-slots.tsx). It is lost on a page reload, although the section’s fields still belong to the old class. It also records the class from before the latest change rather than the class the fields came from. A second change therefore names the wrong one: the note said “extracted as W2” for fields extracted as Bank-checks. The per-section Re-extract that #1672 needed now works correctly when it is offered. Filed as #1816.

3. A test set created from S3 files with no baselines fails after being reported created (product defect)

Section titled “3. A test set created from S3 files with no baselines fails after being reported created (product defect)”

Tier G. The From files in S3 wizard, pointed at documents with no baseline files, says on one step that unlabeled documents will arrive and in a hint that they are skipped. It then reports the set as created, and the set ends in FAILED. Adding documents is then refused because the set is “not in COMPLETED status”, so the only remedy is to delete and recreate it. Whether v0.6.13 behaves the same way was not checked. Filed as #1817.

  • One run returned a shortened list as a success. The fifth v0.6.14 run returned one of the Payslip’s three FederalTaxes rows (Social Security and Medicare are missing). 5. The A/B asymmetry the v0.6.13 record left open recurred on v0.6.13 and not on v0.6.14 (improvement, inferred)

Section titled “5. The A/B asymmetry the v0.6.13 record left open recurred on v0.6.13 and not on v0.6.14 (improvement, inferred)”

The v0.6.13 record found that two of three v0.6.13 runs of the bedrock_llm arm split longdesc_100, a one-section document, into two sections, against none of three on v0.6.12. It left open whether this was a release effect or OCR run-to-run variation. In this pass’s PREV side, v0.6.13 split it in two of three runs again, and v0.6.14 split it in none of three. That reading is inferred from n = 3 per side, and no single change in this release has been identified as the cause.
