WHY: BANK_CHECK's schema has exactly ONE property, an array named `checks`, so the
class already models several checks per sheet. Nothing was collapsing to a single
record, so there was no loss to avert.

WHAT THE 18 FLAGS ACTUALLY ARE: `extraction_multi_instance_suspected` fires when
probe_count > instance_extracted_count. `instance_extracted_count` is 1 for a class
that declares no instance axis — TRUE WHETHER THE RECORDS ARE MISSING OR SITTING
INSIDE A DECLARED ARRAY. So the predicate cannot distinguish the two, and the
detection numbers alone can never establish data loss. Here it correctly identified
that BANK_CHECK never declares `x-aws-idp-instance-array: checks` — a real
configuration finding in a shipped preset, and free to fix.

An earlier version of docs/benchmarking/feature-multi-instance.md asserted "each of
those 18 documents silently ships 1 to 7 checks fewer than it contains" from the
detection numbers alone, without counting extracted rows. That was false. This file
is the measurement that settles it.
