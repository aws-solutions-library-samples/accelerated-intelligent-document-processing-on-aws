## Verdict

⚠️ **Ship with two product defects to fix in a patch release, both in paths this release adds
or changes.** The published artifact deploys in all six shipped configurations, both template
transforms deploy and process a real document, the CloudFormation upgrade from 0.6.15 completes
with no consistent change in extracted values, all four security gates pass, and the 342-run
release A/B shows **0 regressions** with recall and cell accuracy identical over the same 23,370
compared cells. Advanced-mode extraction is markedly cheaper on this release (Finding 3).

**The two defects:**

1. **A document sent back from review, or reprocessed from a step, is scored at 100% confidence
   and completes without review** (Finding 1). The tracking table does not persist each page's
   OCR-confidence location, so a document rebuilt from it for a rerun reaches assessment with
   no OCR confidence data. In the browser review a document that had raised six confidence
   alerts on its first run came back from **Send back** with every non-empty field at exactly
   100.0% and no alert, and completed. Send back and Reprocess-from-a-step are both new in this
   release, and Review Routing is now on by default for new stacks, so the path that is meant
   to keep a document under review is the one that releases it.
2. **An in-place Terraform upgrade from 0.6.15 leaves the state machine's role without one of
   its inline policies until a second `terraform apply`** (Finding 2). The module names inline
   policies by position; a renumbered policy is replaced, and the replacement's late destroy
   deletes the newly created policy of the same name. The missing grant is
   `lambda:InvokeFunction` on the pipeline-hooks dispatcher.

**Every tier has a result.** Tiers B, D, E, F1, H and J pass. Tier A passes except `make test`,
which fails on five story-catalogue tests that also fail on `develop` (Finding 4); the same five
take the `scripts` tree out of the coverage ratchet. Tier C passes five of six variants; the
tenant-isolation harness passed 22 of 23 checks, and its one failure is the harness's, which does
not accept a document held for review (Finding 5). Tier G passed 15 flows, failed one (Finding 1)
and was blocked on one. Tier K failed (Finding 2). Tier I reached no verdict, because the parity
tool's normalisation does not cover most of what it reported (Finding 7). Tier F's guidance
refresh (F2–F4) is carried by the sibling benchmark pull request.

Several test-tooling defects were found and are recorded separately from the product findings
(Findings 4–8). Three of them blocked a tier until patched locally, uncommitted, in the
validation worktree; each patch is described where it was used, and none touches shipped code.

## Findings, most important first

### 1. A document sent back from review, or reprocessed from a step, is scored at 100% confidence and completes unreviewed (product defect, this release)

**Measured in the browser (tier G).** `lending_package.pdf` under a profile with Review Routing on
raised six confidence alerts on its first run and was held in the Default queue. As Reviewer, the
document was claimed, one field corrected, and **Send back for reprocessing** chosen; separately,
as Admin, **Reprocess › Start at Assessment** was run on the same document. Both runs ended
`COMPLETED` with 0 alerts and Review Status N/A. In section 1 every non-empty field scored exactly
100.0% and every empty field 0.0%, after both runs; a normal first run of the same file scored 23
fields at 100.0%, 9 at 99.0% and the rest between 55% and 94%. The Processing Flow shows the
assessment step succeeding on every section, in 2–7 seconds each.

**Measured in the logs.** The assessment function logged `Failed to generate text confidence data
for page N: No module named 'pypdfium2'` exactly six times — once per page — in each of the two
reprocessing windows, and never in the document's first run or in two windows in which only the
benchmark battery was running. The log lines do not name the document.

**Read in the code at the tag.** `idp_common/dynamodb/service.py` writes each page of the tracking
record with `ImageUri`, `TextUri` and `OcrPageDataUri` but not `TextConfidenceUri`, while the
reader that rebuilds a `Document` from the record reads `TextConfidenceUri` (always absent) and
sets the page's raw text location to `TextUri`, the parsed text. The reprocess resolver rebuilds
the document through that reader. `AssessmentService._get_text_confidence_data` therefore finds no
confidence file and falls back to regenerating it through `OcrService`, an import that needs
`pypdfium2`, which the assessment function's `[assessment]` extra does not install; the fallback
returns an empty confidence block. Even with the module present, the fallback would be handed
parsed text rather than the raw OCR response.

**Inferred, not traced:** that an assessment prompt with an empty OCR-confidence block is what
yields the uniform 100% scores.

**Why it matters.** Send back exists to put a document back under review, and the dialog says the
document "can return to a review queue afterwards". Instead it comes back with perfect scores and
completes, and nothing on the page says assessment had no data. Review Routing is on by default
for new stacks in this release, so this is the default review path. Filed as [#2258](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/issues/2258).

### 2. An in-place Terraform upgrade from 0.6.15 drops one inline policy from the state machine's role (product defect, Terraform module)

**Measured (tier K).** After `terraform apply` of the 0.6.16 module over a 0.6.15 deployment, the
next plan wanted to create
`module.idp.module.patternstack.aws_iam_role_policy.document_processing_state_machine_role_15`,
named `DocumentProcessingStateMachineRolePolicy15`, granting `lambda:InvokeFunction` on the
pipeline-hooks dispatcher function.

**Read in the apply log.** The upgrade plan renamed the existing `..._role_14` policy from
`DocumentProcessingStateMachineRolePolicy15` to `...Policy14`, which forces replacement, and added
`..._role_15` under the name `...Policy15`. The apply created `..._role_15` first and destroyed the
deposed `..._role_14` object afterwards. An inline policy is identified by role and name, so
destroying the deposed object deleted the policy `..._role_15` had just created. The role then
lacks the grant until a second apply recreates it.

**Inferred, not measured:** what this does to processing between the two applies. A workflow that
calls the pipeline-hooks dispatcher would be refused; the tier K driver stops at the
non-converging plan, so no document was processed on the upgraded deployment. The same position
numbering applies to every role with several inline policies, so any release that inserts a policy
ahead of others can do this to other roles. Filed as [#2259](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/issues/2259).

### 3. Advanced-mode extraction costs about half as much on 100-row documents (improvement, cause inferred)

In the F1 A/B, the configurations were byte-identical on both sides, so the change is the code's.
Every advanced-mode cell cost 45–52% less on the two 100-row documents, with per-run ranges that do
not overlap: `core-tt-adv-sep` on `longdesc_100` cost $0.248–$0.288 a run on v0.6.15 and
$0.113–$0.153 on v0.6.16; `core-bda-adv-sep` on `small_narrow` $0.173–$0.207 and $0.089–$0.121.
The single-page `tiny_form` cost the same on both. Recall and cell accuracy were identical.

The CHANGELOG's fix "Agentic table extraction no longer counts a table's header rows as data on
some runs" also changed the table tool to parse the section's own OCR text, so the agent no longer
spends output tokens reproducing the table. That is the likely cause; the token split per call was
not examined. `aggregate.py --compare` labels these cells inconclusive (Finding 8 explains why it
cannot see a consistent per-document change).

### 4. `make test` fails at the tag, and on `develop`, on five story-catalogue tests (test tooling)

All five failures are in `scripts/tests/test_ux_test_stories_*.py`, and the same five fail on
`develop` at `587409c58`. They check `scripts/ux_stories.toml` against text the release
preparation edited: the `send-a-review-back` story quotes the CHANGELOG lead "More review
outcomes.", which the prepared CHANGELOG renamed "More ways to end a review."; the `docs/rbac.md`
permission table gained a "View/Edit configuration" row the catalogue parser does not know; and the
`take-the-guided-tour` story is no longer selected by its entry now that the entry sits in a
released section. No product code is involved. It also takes the `scripts` coverage tree out of
the coverage ratchet for this release (see *Test coverage*). Filed as [#2260](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/issues/2260).

### 5. The tenant-isolation harness cannot accept a document held for review (test tooling, triggered by this release's default)

The failing row, `ingest:tiv-a-prefix-with-tiv-b-metadata`, uploads a document under tenant A's
prefix naming tenant B's profile in its metadata. The document was processed under `tivA-default`,
tenant A's own profile, and B's profile was ignored — the outcome the harness's own comment calls a
pass. It failed because the document was then held for review (`HITL_IN_PROGRESS`), since a new
stack now has Review Routing on, and the harness waits only for `COMPLETED` or `FAILED`
(`idp_sdk/_core/tenancy_verify.py`). Isolation held; the harness needs to treat a held document as
processed. Filed as [#2261](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/issues/2261).

### 6. The RBAC dynamic test could not change the app client's auth flows (test tooling, environment-triggered)

`scripts/rbac_common.py::set_auth_flows` reads the Cognito app client with
`describe-user-pool-client` and writes it back with `update-user-pool-client`, dropping a fixed
list of read-only fields. `aws-cli` 2.41.0 now returns `ClientType`, which the update refuses, so
the first run stopped before any dynamic check and before ZAP; its restore step failed the same
way, and the client was checked afterwards and found unchanged (`ALLOW_REFRESH_TOKEN_AUTH`,
`ALLOW_USER_SRP_AUTH`). Adding `ClientType` to the read-only list in the validation worktree
(uncommitted) let the rerun complete. Filed as [#2262](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/issues/2262).

### 7. Two Terraform tier drivers failed before measuring anything (test tooling)

- **The Terraform upgrade driver** (`scripts/sdlc/terraform_upgrade_test.py`) fails in preflight
  with `AttributeError: 'Settings' object has no attribute 'variant'`, at the tag and on `develop`:
  it inherits identity checks from the migration driver that read `variant` and
  `upstream_iam_path`, which its own `Settings` never defines. Its 100 offline tests pass because
  none runs the real preflight. Adding the two fields with their base defaults (uncommitted) let
  tier K run.
- **The parity tool** (`terraform/tools/parity.py`) stops at the first resource type whose Cloud
  Control identifier is compound — here `AWS::Cognito::UserPoolGroup`, whose physical id `Admin` is
  not a valid identifier for `UserPoolId|GroupName` — because it tolerates only
  `UnsupportedActionException` and `TypeNotFoundException`. Treating Cloud Control's
  `ValidationException` as "not readable" (uncommitted) let the second run complete, at the cost of
  38 resources listed rather than compared. Separately, its baseline and name normaliser do not
  cover Terraform's generated queue names, KMS key ids, empty `VpcConfig` or CloudFormation's own
  tags, which is most of tier I's 166 unexplained differences, and the normaliser rewrites
  substrings inside values.

Filed as [#2263](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/issues/2263).

### 8. Two measurement instruments reported a clean result they had not established (test tooling)

- **SRT.** The first scan of the pass exited 0 with "no high-priority security issues found",
  but Semgrep had not run: a stray `~/.local/bin/pysemgrep` on the host shadowed SRT's own and
  crashed on import. SRT's scanner-health check printed the omission, and the exit code did not
  reflect it. The scan counted in this record was re-run with SRT's own environment first on
  `PATH`, and every scanner completed. The stray copy belongs to the host, not the repository;
  the exit code is the repository's.
- **The A/B comparison.** `aggregate.py --compare` judges a cell's cost change against the cell's
  spread pooled across its three documents, whose sizes differ by a factor of 100, so a consistent
  per-document halving (Finding 3) reads as "within noise". A per-document paired comparison would
  report it.

### 10. The browser review's usability and French findings (tier G)

Ranked, abbreviated; Finding 1 is the most important of them as a user sees it.

1. **A routing rule can silently re-hold every reviewed document.** A custom rule without a
   "Reviewed false" condition, placed first, re-places a reviewed document up to "Maximum
   placements in a row" times. All three built-in rules carry the guard; the tab does not warn
   when a new rule lacks it.
2. **The Default queue's "Routing rules that use this queue" panel took 33 seconds** (27 paged
   requests) and listed 531 rows: the three built-in rules for each of 177 profiles, including
   profiles with Review Routing off.
3. **The Reprocess dialog shows no run plan**, while Process Changes does, and it offers Policy Rule
   Validation as a start step when that step is off; Process Changes then says "Starts at Policy
   Rule Validation" for a step it lists as Not enabled.
4. **Raw identifiers in the UI:** `HITL_IN_PROGRESS` in both languages, state-machine state names in
   the Processing Flow (each map iteration listed twice), `NO_BASELINE`, "Decision_model Pricing".
5. **Reject and Complete give no confirmation; Send back does.**
6. **Smaller:** alert chips without a parent path; a held document shows a "Completed" timestamp
   and a duration that includes review idle time; the Viewer's Welcome page and tour describe
   actions a Viewer cannot take, and every tour step is titled "Task 1"; the upload page keeps the
   file selected after a successful upload.

**French (Canada).** The language menu switches the page (`lang="fr-CA"`), and dates, decimals and
percentages are formatted for French. What only the French shows: column headers and timestamps cut
off in the Document List and on configuration profiles; the routing reason and built-in rule labels
on the Reviewer's main screen are still English, as are most Configuration tabs and the Pricing
page (the CHANGELOG discloses English admin screens, but these are on the review screen); file
sizes in English format ("2.62 MB"); "Claim" translated three different ways on one screen; and
steps that have not yet run marked "Exécutée".
