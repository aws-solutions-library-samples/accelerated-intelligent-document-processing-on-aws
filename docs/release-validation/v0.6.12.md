## Verdict

✅ **Ship, with one finding a maintainer should read before the next release** — the published
artifact deploys in all five shipped configurations, both template transforms deploy and
process a real document, the upgrade from 0.6.11 applies without rollback, and the 342-run
release A/B shows **0 regressions and 0 improvements**.

**6 of 8 tiers pass. Tier G (browser UX) is NOT RUN** — no Chrome or Chromium on the
validation host, nothing on `127.0.0.1:9222`, and the `browsermcp` MCP server disconnected
mid-session rather than being absent. **Tier F is PARTIAL**: F1, the release A/B, is complete;
**F2–F4, the guidance-paper refresh, was not run** — it is a second day of work and roughly
$2,000 of Bedrock and Textract spend, and the budget decision was referred to the requester
and not granted during this pass. Both are recorded below with what that leaves unmeasured.

**The finding that matters is in tier E, and the aggregate numbers hide it.** Diffing the
document processed before and after the upgrade gives 38 differing leaves of 1,852, while two
*same-version* control runs differ from each other on 56 of 1,860 — so by totals alone the
upgrade moved **less** than the model's own run-to-run variation, and "no change" is the
conclusion the numbers invite. Two groups of differences are nonetheless identical across all
three 0.6.12 runs and differ from 0.6.11, which is a version effect rather than noise: **six
Payslip statutory-tax amounts changed sign**, and the driver's-licence section populates one
field fewer. Neither is in the CHANGELOG. See Finding 1.

**Three findings are improvements on 0.6.11, two of them closing items that record raised.**
The curated security snapshot now reads PASS on all four gates where 0.6.11 published
`SRT — FAIL ❌`; the `idp_common` integration suite went from 1 failure of 19 to **19 of 19**;
and the coverage registry grew from 9 trees to 11, which moved the lowest-covered tree.

## Findings, ordered by how much they matter

### 1. Two reproducible, unannounced changes in extracted values across the upgrade — product, this release

`samples/lending_package.pdf` was processed four times: once on 0.6.11 before `update-stack`,
once on 0.6.12 after it, and **twice more on 0.6.12** as a same-version control. Timings,
`processing_report` free text and `confidence_reason` strings were excluded as noise.

| comparison | common leaves | differ | only-A | only-B |
|---|---:|---:|---:|---:|
| 0.6.11 vs 0.6.12-post | 1,852 | **38** | 20 | 2 |
| 0.6.12-ctrl1 vs 0.6.12-ctrl2 | 1,860 | **56** | 0 | 7 |
| 0.6.12-post vs 0.6.12-ctrl1 | 1,853 | 16 | 1 | 7 |
| 0.6.12-post vs 0.6.12-ctrl2 | 1,853 | 62 | 1 | 14 |

⚠️ **Read the totals and you get the wrong answer.** The upgrade diff (38) is *smaller* than
the same-version control diff (56), which says the upgrade moved less than the model's own
variation. Two groups of differences are nevertheless identical in **all three** 0.6.12 runs
and differ from 0.6.11 — agreement across repeats on one side is what separates a version
effect from noise, and a single run per side cannot see it.

**(a) Six Payslip statutory-tax amounts changed sign.**
`inference_result.{City,Federal,State}Taxes[*].Period`: 0.6.11 returns `'40.60'`, `'28.05'`,
`'6.56'`, `'8.43'`, `'5.94'`, `'0.60'`; every 0.6.12 run returns exactly those negated. The
field is declared `Period: "Current period amount for this federal tax item"` and evaluated
`NUMERIC_EXACT`, so the sign is scored rather than cosmetic.

Textract reads those lines as `- - 40.60`, `-6.56`, `- 8.43`, `- -5.94`, `- -0.60` under the
document's `Deductions / Statutory` heading, so the negative is arguably the more faithful
reading of the page. ⚠️ **That is inference from the OCR and the column heading, not a
measurement of correctness**: `samples/lending_package.pdf` has no ground-truth baseline in
the repository, so this record cannot say whether 0.6.12 corrected a long-standing error or
introduced one. Either way an operator comparing extracted tax figures across this upgrade
sees a sign change with nothing announcing it.

**(b) The driver's-licence section populates one field fewer.**
`metadata.population_check.fields_populated` 9 → 8 and `population_ratio` 0.818 → 0.727,
identically in all three 0.6.12 runs, because `ENDORSEMENTS` returns an empty list where
0.6.11 returned `['NONE']`. This also rewrites the `extraction_incomplete` processing issue to
name `ENDORSEMENTS, RESTRICTIONS` instead of `RESTRICTIONS` alone, and removes the
`metadata.coercion` block — 0.6.11 recorded a `type_family_mismatch` refusal on a null
`RESTRICTIONS` that 0.6.12 does not produce.

**A contrast that validates the method:** section 3's `fields_populated` also moves (0.6.11
and 0.6.12-post both 8, both controls 9). Same shape as the two above, but it fails the
agreement test, so that one **is** nondeterminism.

**Mechanism not isolated.** `config_library/` is unchanged between the tags apart from
`pricing.yaml`, `model_config_limits.yaml` and `extensions-marketplace.yaml` — nothing in the
lending-package preset — so the configuration is identical on both sides and the cause is in
code. `lib/idp_common_pkg/idp_common/extraction/service.py` gained 367 lines this release and
nothing in the diff mentions sign, negation or absolute value. **Neither change appears in the
0.6.12 CHANGELOG.** Both deserve either a changelog entry or a fix.

### 2. The lowest-covered tree changed, and one tree lost coverage inside the ratchet's tolerance — gate, pre-existing

The coverage registry grew from 9 trees to 11: `src_lambda` (89.90%) and **`api_resolvers`
(71.01%)** are new since the v0.6.11 record. `api_resolvers` is now the lowest-covered tree by
11 points, displacing `seller_entitlement` (82.03%), which the previous record named as the one
to watch. `api_resolvers` holds the UI API resolver Lambdas — the layer this release moved
*every document read* behind (#1033) — so it is the tree where low coverage costs most right
now.

Separately, **`main_stack_extensions` measured 93.86% against the previous record's 95.64%, a
loss of 1.78 points**, which the per-file ratchet's 1% tolerance absorbed, so
`make check-coverage-debt` stayed green. That is the ratchet behaving as designed and is
exactly why the release record carries the measured per-tree table and its delta: a tree can
lose coverage with every gate green.

### 3. Tier F2–F4 was not run, so `docs/benchmarking/` still carries v0.6.11 data — process, this pass

Only F1 ran. Every file under `docs/benchmarking/` therefore still cites measurements from
v0.6.11 and **no number in it describes this release**, including `config-guidance.md`'s header
and its §5 model-selection section. Unmeasured on this build, specifically:

- the configuration matrix (`coresynth`/`core`), so no cross-config grid for 0.6.12;
- the scaling study, so **where each mode's completeness cliff sits on this release is
  unknown** — and this release changed truncation handling (`extraction_output_truncated`) and
  the row-shortfall check (`extraction_partial_row_shortfall`, residual tolerance now 29 rows
  rather than a ratio), which are precisely the signals that study reads;
- cost level and variance at the shipped default model;
- the two standing list-loss hazards (`intconf`, `advverify`), so this record cannot say
  whether either is still open;
- the model sweeps, so **Claude Sonnet 5.5 — the model this release adds — has no measured
  accuracy, completeness or cost figure anywhere**, which matches the CHANGELOG's own
  statement that it is in no benchmark sweep.

### 4. SRT's open-finding count rose 7 → 10 — test code, explainable

All ten are Bandit `B105`/`B106`: matches of an *identifier's name* against a password
wordlist, in test files no deployment artifact is built from, reported at Bandit's own severity
rather than blocking. The three new ones are `test_delete_documents_selector_failure.py`,
`test_delete_documents_coverage.py` and `test_batch_delete_selector_failure.py` — test files
this release added with the document-deletion fix (#1366). Nothing reopened and the
suppression register is non-vacuous at 52 entries. No action; recorded because any movement in
a gate value is a finding.

### 5. Tier G could not run, and this is the release where that costs most — environment

No Chrome or Chromium on the validation host, nothing listening on `127.0.0.1:9222`, no
`chrome-devtools` MCP, and `browsermcp` **disconnected during the session** rather than being
absent. This is the second consecutive release with tier G NOT RUN.

It matters more here than at 0.6.11 because this release's UI surface is large: page rotation
in four editors, the "why this field has no bounding box" control on all four field-displaying
surfaces, Test Studio's server-side document search, the annotation-queue advance, the
prefix-mapping admin screens, the malware-scan banner and detail field, and the cost panel's
unpriced-unit handling. The compensating coverage is the **UI unit suite — 124 files, 1,507
tests, all passing** — which runs in neither `make test` nor `make lint-cicd` and was invoked
separately. **Unit coverage is not a person completing a flow**, and no flow in
`scripts/ux_flows.yaml` was exercised.

### 6. A test writes build output into the tree, which silently degrades the next SRT scan — test tooling, pre-existing

`lib/idp_sdk/tests/unit/test_multi_doc_discovery_source_zip.py` writes a ~7 MB
`.aws-sam/multi-doc-discovery-source.zip` into the **repository root** while it runs. Any
`make srt-scan` ordered after `make test` therefore reports `1 .aws-sam build directory
present` and drops into its degraded mode, emitting phantom LOCAL-ONLY findings and risking a
checkov crash on the largest templates.

The scan segregated them correctly, so the gate verdict held — but the preflight rule in
`.claude/skills/release-validation.md` is "scan before `publish.py`", and that is not
sufficient: it has to be before `make test` too. Either the test should write to a temporary
directory, or the preflight rule should say so.

### 7. `ruff` on PATH is not the pinned version, and the warning is easy to pass over — gate, environment

`make lint-cicd` printed `⚠️ ruff 0.15.20 is first on PATH, but this repo pins ruff 0.15.13`
and then **passed**. Findings and formatting are both properties of the linter version, so a
green run under the wrong one does not establish the CI result. Re-run under the pinned
version via a shim (`uvx ruff@0.15.13`): `make ruff-lint check-lint-debt` exits 0, `ruff check
--fix` modified nothing, and the lint-debt gate reports 82 files excluded from `ruff check`
and 171 from `ruff format`, all carrying exactly their recorded findings. So the gate is
genuinely green — but it was green for the wrong reason until re-run, and the warning is one
line in a long log.

### 8. RBAC dynamic grew 609 → 876 checks; 17 are skipped and a skipped check asserted nothing — test, informational

Movement is in the expected direction and consistent with the release's new API surface
(`getFilePresignedUrls`, the prefix-mapping operations, the malware-scan fields). The
operation × role matrix grew 580 → 605, so most of the growth is outside the matrix. Skips
moved 15 → 17 and sit in three suites: 11 in the positive authorization matrix, 3 in
config-version scope enforcement, 1 in token lifecycle (with its 1 known-gap warning), 2 in
*Other*. 0 hard failures and **0 checks that could not be run**, which is the distinction that
matters — a check that could not run establishes nothing.

### 9. A defect open across two releases has closed — product, improvement

`idp_common`'s integration suite is **19 passed, 0 failed, 0 skipped** (11,859 deselected). At
v0.6.11 it was 1 failure of 19, and that failure reproduced identically at v0.6.10. This is the
only tier that exercises the library against real Bedrock, Textract, S3 and DynamoDB rather
than `moto`, so it is not covered by `make test` or by either CI.

`idp_cli` is unchanged and is **not** a pass: `-m integration` collected 1,494 tests and
selected **0**. An empty suite asserts nothing.

### 10. The security snapshot's SRT gate stopped contradicting the live scan — gate, improvement

0.6.11's curated snapshot published `SRT — FAIL ❌ (7 open/reopened HIGH)` for a release whose
live scan was green, because the curator counted the scoped-out identifier-name findings as
blocking while the scan did not. 0.6.12's snapshot reads `PASS ✅ (0 open/reopened HIGH of
38,891 tracked, 10 scoped out)` — the curator now applies the same scope decision. The
previous record logged this as a finding; it is closed.

### 11. Four orphaned ENIs in the stack-test VPC, two of them not from this run — environment

After the two VPC tiers, `describe-network-interfaces --filters status=available` in the
stack-test VPC returned four. Two named this run's deleted `apigwpriv` stack and were deleted.
**Two name an `idpmwjobs` stack that is also gone but is not from this run, and were left in
place** rather than deleting another session's resources. They will eventually block a VPC or
security-group delete and should be cleared deliberately.

## What was NOT validated

- **Real GovCloud.** Tier D's `--govcloud` run was `REGION=us-west-2` with commercial
  credentials. Partition ARNs, GovCloud model availability and the BDA project rejection are
  unproven — the class of defect that shipped as #676/#677. The Knowledge Base was also
  disabled in that run.
- **The web UI as a person uses it.** Tier G NOT RUN (Finding 5). No flow in
  `scripts/ux_flows.yaml` was exercised on this build.
- **Everything tier F2–F4 answers** (Finding 3): the configuration matrix, the scaling
  cliff, cost variance, the two standing list-loss hazards, and every selectable model's
  measured row — including **Claude Sonnet 5.5, which this release adds and which has no
  measured figure of any kind**.
- **The seller positive path.** No token was issued or verified; the tier asserts refusals
  only.
- **`idp_cli` integration behaviour.** The suite is empty (Finding 9).
- **Whether Finding 1's sign change is a correction or a regression.** There is no
  ground-truth baseline for `samples/lending_package.pdf` in the repository, so correctness
  could not be scored — only the change, and its reproducibility, were measured.
- **Canada (`ca-central-1`).** This release adds it as a published region with its own model
  mapping. Nothing in this pass deployed there; all stacks were `us-west-2` (seller
  `us-east-1`).
- **Malware scanning.** The new `MalwareScanning` parameter defaulted to `DISABLED` in every
  stack here, so no gate decision, quarantine path or GuardDuty verdict was exercised.
